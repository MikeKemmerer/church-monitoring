Architecture Overview

The monitoring system uses a pull model with two components:

  • Clients (agents) — run on each monitored host. An Apache vhost on port 8033 serves cached status data over HTTPS with mutual TLS authentication.
  • Server (dashboard) — runs on the primary host. Apache on the configured port serves the dashboard UI and proxies requests to clients using client certificates.

Clients collect system metrics and service status every 5 minutes via cron, writing a cached JSON file. The dashboard fetches this cache on demand — near-instant response.

Components

Client-side (each monitored host)

  • status.cgi — serves the cached status JSON
  • cec-check.cgi — on-demand CEC TV status (button-triggered, not polled)
  • collect.sh — cron script that gathers metrics and writes the cache
  • client-config.json — defines which services/processes to monitor

Server-side (dashboard host)

  • index.html — dashboard UI (this page's sibling)
  • fetch-status.cgi — aggregates status from all clients
  • fetch-cec.cgi — proxies CEC check to a specific client
  • enroll.cgi — handles client certificate enrollment
  • server-config.json — lists all monitored clients

Initial Setup

1. Install the server

sudo ./install-server.sh

The installer will:

  1. Install required packages (apache2, openssl, jq)
  2. Create a Certificate Authority (CA) for mutual TLS
  3. Generate the server's client certificate
  4. Configure the dashboard Apache vhost (default port 8080)
  5. Set up HTTP basic authentication
  6. Generate the first enrollment token

Note the enrollment token displayed at the end — you'll need it for client setup.

2. Install each client

sudo ./install-client.sh

The installer will prompt for:

  • Server address and port (e.g., server-ip:8080)
  • Enrollment token (from server setup or generate-token.sh)
  • Which services to monitor (auto-detected, y/n for each)

The installer automatically generates a TLS certificate, enrolls with the server, and sets up the monitoring agent.

Adding New Clients

After initial setup, to add more monitored hosts:

  1. On the server, generate a new enrollment token: 
    sudo /usr/local/bin/generate-token.sh
  2. On the new client, run the installer with the new token: 
    sudo ./install-client.sh

Each token is single-use and is automatically deleted after successful enrollment.

Certificate Management

  • CA certificate — valid for 10 years. Stored at /etc/church-monitoring/ca/
  • Client certificates — valid for 2 years. Renew by running: 
    sudo ./install-client.sh --renew
  • Server certificate — valid for 2 years. Regenerate via: 
    sudo ./install-server.sh --renew-cert
  • To manually sign a CSR: 
    sudo /usr/local/bin/sign-csr.sh <path-to-csr>

Service Configuration

Edit /etc/church-monitoring/client-config.json on each client to change monitored services:

{
    "hostname": "host-a",
    "monitors": [
        {"name": "apache2", "type": "systemd"},
        {"name": "church-calendar", "type": "systemd"},
        {"name": "vlc", "type": "process"}
    ],
    "cec_enabled": false
}

Types: systemd checks systemctl is-active; process checks pgrep.

Changes take effect on the next cron collection (within 5 minutes).

CEC TV Status

CEC checks are on-demand only — triggered by the "Check TV" button on the dashboard. This avoids blocking the CEC adapter and is only useful when you're actively looking at the dashboard.

The check reports TV power state (on/standby) and active HDMI input. It has a 5-second timeout to prevent hangs if the CEC adapter is busy.

CEC requires cec-utils installed and the Apache user (www-data) in the video group on the client host.

Collected Metrics

Each client reports:

  • System — uptime, CPU load (1/5/15 min), memory usage, disk usage, CPU temperature
  • Services — systemd unit active/inactive state
  • Processes — running process count via pgrep
  • CEC — TV power and HDMI input (on-demand only)

Password Management

To change the dashboard password or add users:

sudo /usr/local/bin/manage-auth.sh

Troubleshooting

Dashboard shows "unreachable" for a client

  • Verify the client's Apache is running: systemctl status apache2
  • Check connectivity: curl -k https://CLIENT_IP:8033/
  • Verify certificates haven't expired: openssl x509 -enddate -noout -in /etc/church-monitoring/ssl/agent.crt
  • Check Apache error logs: tail /var/log/apache2/church-monitoring-error.log

Stale data (cached time keeps growing)

  • Check cron is running: crontab -l | grep church-monitoring
  • Run collection manually: sudo /usr/local/bin/church-monitoring-collect
  • Check for lock file issues: ls -la /var/run/church-monitoring-collect.lock

CEC check hangs or returns "unknown"

  • Test manually: echo "pow 0" | timeout 5 cec-client -s -d 1
  • Ensure only one process uses the CEC adapter at a time
  • Verify www-data is in the video group: groups www-data

File Locations

Server:
  /etc/church-monitoring/server-config.json    Client registry
  /etc/church-monitoring/ca/                   CA certificate and key
  /etc/church-monitoring/ssl/                  Server client certificate
  /etc/church-monitoring/tokens/               Enrollment tokens
  /etc/church-monitoring/.htpasswd             Dashboard credentials
  /var/www/church-monitoring/                  Dashboard web root
  /usr/lib/cgi-bin/church-monitoring/          Server CGI scripts

  /etc/church-monitoring/client-config.json    Service monitor config
  /etc/church-monitoring/ssl/                  Agent certificate and key
  /var/cache/church-monitoring/status.json     Cached status data
  /usr/lib/cgi-bin/church-monitoring/          Client CGI scripts
